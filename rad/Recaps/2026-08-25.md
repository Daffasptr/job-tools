# 2026-08-25 — Stage 2 progress

## Progress

- Locked in stage 2's scope: paste a job posting + your must-haves (e.g. languages spoken), get back a plain yes/no on whether the posting clashes with one of them, plus the exact sentence that decided it.
- Built the backend for it — a small, separate Node.js/TypeScript/Express server at `job-tools/server/`, holding the Anthropic API key safely (never in the browser), calling Claude with a strict "only flag a clash the posting actually states, don't guess" instruction, and using Zod to force the answer back into a fixed, usable shape (`matches` / `reason` / `quote`).
- Got a real Anthropic API key and tested the server live, twice, against real job postings — both correct: a posting requiring Dutch was correctly flagged as a mismatch (given must-haves of English + Indonesian), and a posting where Dutch was explicitly optional was correctly *not* flagged. That second case matters most — it's the exact "hard requirement vs. nice-to-have" distinction that other tools kept getting wrong for you.
- Walked through the whole stack and the whole project file structure with you afterward — what TypeScript/Node.js/Express/the Anthropic SDK/Zod/dotenv each do and why, plus what every folder and file in the project is for.

## Challenges

- First attempt used an outdated version of the Anthropic SDK (picked from memory, not checked) — it didn't have the `messages.parse` / structured-output helper the plan relied on. Fixed by checking the real published version and upgrading.
- That upgrade then exposed a second mismatch: the SDK's structured-output helper needs a newer version of Zod (the tool that defines the answer's shape) than what was first installed. Fixed by upgrading Zod too.
- Neither was a design problem — both were "picked a version without checking, then let the type-checker and installed-package data correct it," which is exactly what testing before handing it to you is for.

## Next Steps

Stage 2 isn't finished end-to-end yet — the backend works, but there's no way to use it from the actual website. The one clear next step: build a simple form on the site (a box to paste a job posting, a box for must-haves, a button, and a place to show the result) that calls this backend instead of me sending test messages by hand. Once that exists, stage 2 is genuinely done and usable by you directly.

No decisions pending beyond that — just the remaining build step.
